# Java 存量开发

## API 复用与分层

- 按同类复用、同层复用、跨层复用的顺序搜索。
- Service 逻辑优先调用当前类或已有 Service 方法，不得为了方便绕到 Mapper。
- 真实调用已有 API；不得复制其实现后改写，也不得把复制代码称为复用。
- 从声明和既有调用点核对参数、返回值、异常、事务和统一响应格式。
- 修改已定位的已有类和已有方法；新增辅助类不能代替存量修改。
- 保留公开方法签名、既有调用方语义、分层结构和代码风格。

## 测试先行

在修改生产代码之前为每个功能点编写或调整单元测试：

1. 优先沿用项目已有的 JUnit 版本、扩展和断言库；项目已使用 JUnit 时不得另引入测试框架。
2. 测试必须直接覆盖 requirement.md 的功能行为、边界条件和明确的兼容性要求。
3. 优先扩展最接近目标类的已有测试类；只有职责清晰且没有合适测试类时才新增测试类。
4. 隔离外部系统只使用项目已有的 mock、stub 或 test fixture 方式；不要把单元测试升级成依赖数据库、网络或完整容器的集成测试。
5. 先运行新增或修改的相关测试，确认它因尚未实现的目标行为而失败。编译错误、依赖缺失、环境错误或无关断言失败不算有效红灯。
6. 不得为了通过测试而删除断言、跳过测试、吞异常或降低验收标准。

若项目明确采用非 JUnit 测试框架且引入 JUnit 会破坏既有构建约定，沿用现有框架，并在检查证据中说明判断依据。
