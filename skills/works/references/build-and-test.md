# Java 编译与相关测试

## 构建工具选择

优先使用仓库 Wrapper，并先检查文件存在：

- Linux/macOS：`./mvnw`、`./gradlew`，其次为已安装的 `mvn`、`gradle`。
- Windows：`mvnw.cmd`、`gradlew.bat`，其次为已安装的 `mvn`、`gradle`。

使用正斜杠描述路径。不要假设文件系统区分大小写，也不要在命令参数中使用 `cd`、管道、`&&`、通配符或 Bash/PowerShell 专属语法。多模块项目通过构建工具的项目文件、模块或 task 参数定位受影响模块及必要依赖。

## 测试范围

只运行本次功能直接相关的测试：

- 新增或修改的单元测试类/方法。
- 与被修改类、方法及其兼容行为直接相关的已有回归测试。
- 为执行这些测试所必需的同模块测试依赖。

不要把完整项目测试套件、无关模块测试或无关端到端测试加入默认验证范围。若构建工具无法可靠选择单个方法，则选择最小相关测试类；无法选择单个测试类时，选择最小相关模块，并记录范围扩大的原因。

`regression_test` 是不可跳过的门禁。Nacos、MySQL、Redis、消息队列、远程 HTTP 服务等外部依赖与本次修改无关时，不启动、不等待也不连接它们；选择不触发这些依赖的最小相关测试。修改功能确实依赖外部系统时，沿用项目已有的 mock、stub、fake、test fixture 或测试替身隔离外部边界，并继续执行测试；不得因外部服务未启动、连接信息缺失或环境不可用而停止流程、询问是否跳过或仅报告无法测试。若现有测试尚未隔离该依赖，先做最小测试侧调整再执行，不得改变生产行为或降低断言标准。

编译和测试必须通过 `works.py check -- <program> <args...>` 运行真实命令。退出码 0、无失败测试以及输出中的测试统计共同构成通过证据。
